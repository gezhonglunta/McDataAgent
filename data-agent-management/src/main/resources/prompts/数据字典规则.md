# 数据字典规则
业务表里面的字段可能会使用数据字典，需要为用户自动翻译存储值和展示名称。
数据字典的说明通常在字段的描述中出现，比如某字段的描述DDL为：
```sql
COMMENT ON COLUMN t_product.category_code IS '商品分类，使用数据字典：商品分类';
```
这说明`t_product`表的`category_code`字段存储的是数据字典-`商品分类`的`字典项编码`，给用户看到的最终数据必须为`商品分类`的`字典项编码`的展示名称，而不是编码本身。
若字段未明确说明使用了数据字典，但字段说明的语义为：xx类型、xx编码、xx状态、xx等级、xx批次、xx单位、xx阶别、xx工种、xx方式，此时也要默认它们是数据字典，并主动查询数据字典表寻找可能的数据字典配置信息。
## 数据字典表查询规则
- 系统使用2张表：`sy_dict`、`sy_dict_val`来记录数据字典的元数据；
- `sy_dict`是数据字典主表，记录了字典本身的：编码(code)、名称(value)、备注(remark)；
- `sy_dict_val`是数据字典子表，记录了字典项列表，包含：字典项编码(code)和展示名称(value)；
- 两张表的关联关系为：`sy_dict`.`dict_id` = `sy_dict_val`.`dict_id`；
- 业务表里面存储的是 `sy_dict_val` 表的 `字典项编码code`，需要翻译成 `展示名称value`；
- 通过数据字典语义名称(如：商品分类)查询数据字典项列表的SQL示例：
  ```sql
  select d.value as dict_name,d.remark as dict_remark,dv.code as dict_item_code,dv.value as dict_item_name from sy_dict d inner join sy_dict_val dv on d.dict_id = dv.dict_id where d.scope != '0' and d.value like '%商品分类%'
  ```
  **重要原则**
  - 务必使用 sy_dict.value 来检索数据字典，即用数据字典的名称而不是编码来检索
  - 务必增加 sy_dict.scope != '0' 这一条来过滤系统的数据字典，从而聚焦业务数据
  - 查询的结果可能包含多组相似的数据字典，可以再根据remark字段信息和带入字典项编码做进一步区分，如果你无法确定是哪一组，不要猜，请用户亲自确认。
